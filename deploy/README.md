# Deploying ServerSync (Render + Vercel)

The C++ server runs on **Render** (Linux, Docker). **Vercel** cannot run a long-lived socket server, so it only
proxies its own URL to the Render service (`vercel/vercel.json`).

## 1. Render (server + MySQL)

1. Render Dashboard > **New > Blueprint** > connect this GitHub repo. Render reads `render.yaml` and creates:
   - `serversync-mysql`: private service, MySQL 8 (`deploy/mysql/Dockerfile`) with a 1 GB disk. On its first start
     it loads `sql/ecommerce_db.sql` (schema + 52 products). Passwords are generated by Render.
   - `serversync`: web service, the C++ server built by `Dockerfile`. It gets `DB_HOST`, `DB_USER`, `DB_PASSWORD`,
     `DB_NAME`, `DB_PORT` from the MySQL service (the server uses these instead of `db.conf` when they are set).
2. Both use the **Starter** plan: private services and disks are not available on the free plan.
3. The web service may restart once or twice on the very first deploy while MySQL is still initialising. That is expected.
4. Make an admin: sign up on the site, then in the `serversync-mysql` service **Shell** run
   `mysql -u root -p"$MYSQL_ROOT_PASSWORD" ecommerce_db -e "UPDATE users SET role='ADMIN' WHERE email='you@example.com'"`.

## 2. Vercel (proxy)

1. Put your real Render URL (e.g. `https://serversync-xxxx.onrender.com`) in `vercel/vercel.json`, commit, push.
2. Vercel > **Add New > Project** > import this repo > set **Root Directory** to `vercel` > Deploy.
   (Only that folder is deployed, so no source code or SQL is served by Vercel.)

## Local (Windows) is unchanged

`build.bat` + `db.conf` still work exactly as before.
